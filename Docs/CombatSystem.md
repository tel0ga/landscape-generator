# Оружейная система

## Запуск

Открыть `Assets/Scenes/CombatArena.unity` и нажать Play. Альтернатива: меню **Tools → Survival Combat → Open test arena**. Арена создаётся при запуске: игрок, стены, пять мишеней, верстак и предметы из каталога. Пустая сцена до Play — ожидаемое поведение. `CombatRuntime` также автоматически подключает бой к существующему игроку в `MAIN SCENE`.

Настройки находятся в `Assets/Resources/Combat/DefaultCatalog.asset`: 8 видов оружия и 9 типов припасов/модификаций. Подассеты доступны через раскрытие каталога в Project. Для добавления оружия создать WeaponDefinition и добавить его в список каталога; ID должен быть уникальным и постоянным. Изменение ID нарушает совместимость старых сохранений.

Представление использует простые процедурные спрайты и базовые эффекты/звук, чтобы сцену можно было запускать без дополнительного набора графики. Это техническая демонстрация; художественное оформление и окончательный баланс требуют отдельной настройки и проверки в Play Mode.

## Управление

| Команда | Клавиша |
|---|---|
| Прицеливание | Мышь |
| Атака | ЛКМ |
| Перезарядка | R |
| Активное оружие | 1 / 2 |
| Метательный предмет | G |
| Подбор рядом | E |
| Инвентарь и пауза | Tab |
| Сохранить / загрузить | F5 / F9 |

Перемещение и переключение полёта используют существующие действия Player. Боевые действия вынесены в отдельный `CombatActions.inputactions`. Есть базовые привязки прицеливания, стрельбы и переключения для геймпада; полноценная навигация инвентаря геймпадом не реализована.

## Организация кода

- `WeaponDefinition`, профили атак и `CombatCatalog` — общие настройки. `WeaponInstance` — уникальный предмет, магазин, прочность, редкость и модификации. Игровые изменения не записываются в ассеты.
- `Inventory` — 24 ячейки, стопки и проверки вместимости; установка/снятие модификаций и ремонт выполняются целиком или отклоняются без потери предметов.
- `EquipmentController` и `WeaponController` — два слота, метательный слот, перезарядка, интервалы атак и фазы взмаха. `SimpleCombatAI` использует тот же контроллер; демонстрационные мишени пассивны.
- `CombatPhysics`, `CombatProjectile`, `CombatGrenade`, `FireZone` — попадания, стены, проверка пути снаряда, взрыв и огонь. `Health`, `DamageResolver`, `StatusEffectController` — защита, крит, смерть и эффекты. Контроллер движения учитывает отдельную скорость отбрасывания.
- `AimController`, `WeaponView`, `CombatHUD` — положение оружия, отображение состояния, инвентарь и сообщения.
- `CombatWorld`, `WorldItem`, `PersistentDestructible` — мировые предметы и постоянные изменения. Стабильные ID природы привязаны к координатам чанка и точке генерации. Выгрузка представления не означает уничтожение данных.
- `CombatSaveService` — версионированный JSON, проверка идентификаторов, временный файл, замена с резервной копией и восстановление из копии при повреждении основного файла. Незавершённые атаки и перезарядка не восстанавливаются.

## Существующий пул

`CombatPool` — адаптер над `MarchingBytes.EasyObjectPool`, а не отдельное хранилище свободных объектов. Он регистрирует типы боевых объектов и отслеживает только выданные экземпляры. Пул природы продолжает работать через прежний интерфейс. В EasyObjectPool добавлены регистрация пулов во время игры, идемпотентная инициализация и выдача неактивного объекта: владелец, параметры урона и таймеры назначаются до активации.

Снаряды, гранаты, области огня, трассеры и представления предметов возвращаются в этот пул. При загрузке сохранения активные боевые представления освобождаются. Компоненты очищают временное состояние при отключении.

## Сохранения

Файл: `Application.persistentDataPath/survival-{имя сцены}.json`, резервный файл имеет расширение `.bak`. Сохраняются предметы и их ID, экипировка, здоровье, выносливость, позиция, мировая добыча и уничтоженные постоянные объекты. Ключ мира включает настройки генератора; сохранение другого мира отклоняется. Загружать сохранение можно после смерти. Загрузка завершает режим полёта.

## Проверки и ограничения проверки

В этой среде выполнены:

- Компиляция игровых и редакторских скриптов компилятором из установленной Unity 6000.4.8f1 с библиотеками проекта — успешно.
- `Tools/CombatChecks/Run-DataChecks.ps1` — **14 из 14** проверок данных. Это отдельный запуск настоящих классов каталога/инвентаря с минимальными заменами Unity-примитивов; он не проверяет физику, жизненный цикл компонентов, ввод или интерфейс.
- Ассеты каталога, ввода и сцена подготовлены без редактора через `Prepare-Content.ps1`. Их импорт в Unity ещё не подтверждён.

Unity batchmode завершился с сообщением `No valid Unity Editor license found` (код 198); журнал: `Logs/CombatChecks/setup.log`. Поэтому Unity Test Runner, Play Mode, визуальная проверка, перезагрузка сцены с отключённым Domain Reload и Windows Player-сборка **не проверены**. Наличие исходников тестов не означает их успешное выполнение.

После активации Unity запустить EditMode-тесты `CombatTests` и существующие `P1TerrainTests` через Test Runner. `FastProjectileStopsAtThinWallAndPoolResetsState` сам входит в Play Mode. Для Windows-сборки предусмотрен метод `CombatProjectSetup.BuildWindows` (executeMethod); результат: `Builds/Combat/SurvivalCombat.exe`.

Ручная проверка: выстрелы и взмахи через стены; несколько коллайдеров на цели; отмена обеих перезарядок; смена оружия без обхода интервала; поломка и ремонт; переполненный инвентарь; взрыв и собственный урон; повторное использование снарядов; сохранение/загрузка и повторная загрузка чанка; пауза, смерть и полёт; повторный Play Mode с включённым и отключённым Domain Reload.
